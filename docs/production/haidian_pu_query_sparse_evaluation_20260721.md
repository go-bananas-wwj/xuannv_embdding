# 海淀 P10C：PU + Query 稀疏 Polygon 评测

## 目的

验证玄女 P10C `epoch_800` 的 64 维 2026-04 embedding 能否支撑
`1--9` 个用户圈选 Polygon 的即时制图。实现参考
`embedding-api` 提交 `530b8f4` 的 PU + Query 配方，但本实验采用独立测试折，
不复用历史画廊的全域统计量或精选测试样例。

## 严格协议

- 数据划分：海淀 OSM 建筑、道路、水体标签的固定第 0 折；231 个训练 patch、
  25 个验证 patch、64 个测试 patch。
- 支持标注：每档从训练折中按固定随机种子抽取 `1 / 3 / 5 / 9` 个连通 Polygon；
  测试标签从不参与原型、背景、阈值或 support 选择。
- 模型：不训练神经网络。支持 patch 的全部 embedding 像素估计通道均值/标准差，
  逐像素标准化并 L2 归一化；每个 Polygon 等权构造前景原型。
- PU 可靠背景：正样本外膨胀 3 像素，保留与前景最不相似的 30% 未标注像素，
  每支持 patch 至多 2048 个背景像素。
- 评分：`cos(x, fg) - 0.65 * cos(x, bg)`；在支持正样本与可靠背景上扫描 180 个
  阈值，以 F0.5 选择阈值。Query 阶段使用 `sigma=0.55` 平滑、99.7% 置信分位、
  12% Query 融合和面积增长保护。
- 报告：仅在 64 个独立测试 patch 汇总 Precision、Recall、F1、IoU、AUC、AP。

## 结果

| 类别 | Polygon | F1 | AUC | AP | Query 适配 patch / 64 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 建筑 | 1 | 0.237 | 0.714 | 0.228 | 59 |
| 建筑 | 3 | 0.328 | 0.781 | 0.261 | 51 |
| 建筑 | 5 | 0.354 | 0.830 | 0.288 | 58 |
| 建筑 | 9 | 0.359 | 0.835 | 0.294 | 57 |
| 道路 | 1 | 0.269 | 0.522 | 0.182 | 64 |
| 道路 | 3 | 0.357 | 0.685 | 0.248 | 62 |
| 道路 | 5 | 0.455 | 0.799 | 0.435 | 60 |
| 道路 | 9 | 0.430 | 0.770 | 0.492 | 61 |
| 水体 | 1 | 0.111 | 0.793 | 0.520 | 60 |
| 水体 | 3 | 0.131 | 0.767 | 0.081 | 61 |
| 水体 | 5 | 0.108 | 0.830 | 0.269 | 63 |
| 水体 | 9 | 0.184 | 0.795 | 0.095 | 59 |

## 解读与边界

1. 建筑和道路在 1 到 5 个 Polygon 时明显提升：建筑 F1 `0.237 -> 0.354`，道路
   F1 `0.269 -> 0.455`。这支持“少量用户标注可启动候选制图”的产品定位。
2. 9 个 Polygon 不必然优于 5 个：其语义多样性和位置对原型影响很大，实际接口应
   保留可视化预览、用户补样和切换到 `>=10` Polygon 的 Conv3x3 训练路径。
3. 水体的 AUC 可达约 `0.83`，但 F1 很低。这不是 embedding 完全失去排序能力，
   而是 OSM 水体的稀疏/不完整标签与支持背景 F0.5 阈值在严格独立测试上发生校准
   偏差。它不应作为当前 PU 产品的直接自动制图承诺；适合以热力候选图配合人工复核，
   或使用 10 个以上 Polygon 的轻量分割头。
