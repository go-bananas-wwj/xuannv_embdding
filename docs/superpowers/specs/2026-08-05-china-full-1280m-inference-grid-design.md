# 中国全国 1,280 米推理网格设计

## 1. 目标

建立一套可复现、可审计的全国完整规则网格，统一服务于：

1. 全国训练样本抽取。
2. 2020 年和 2021 年季度多源数据下载与裁切。
3. 全国季度嵌入推理、结果拼接和缺块检查。
4. 当前 62,000 个采样候选的父网格成员关系验证。

全国完整网格是空间主注册表。后续训练采样和推理任务不得另行建立不同原点、
不同 UTM 归属或不同 patch 编号的网格。

## 2. 当前事实与边界

现有 `national_macrocell_inventory.jsonl` 只包含 60,043 个
12.8 km x 12.8 km 宏网格及其土地面积估算，不是逐 patch 的精确全国图集。
现有 62,000 个候选遵循相同的 1,280 米 UTM 网格规则，但基础层主要来自历史
候选骨架修复，并不是从已经物化的完整全国 Shape 中直接抽取。

本次工作将补齐完整父网格，并检查 62,000 个候选是否都能映射到唯一父 patch。
该网格只解决空间划分，不代表每个 patch 已经通过季度影像质量检查。

## 3. 网格规则

1. 单个 patch 为 1,280 m x 1,280 m。
2. 每个 patch 对应 128 x 128 个 10 米像素。
3. 相邻 10 x 10 个 patch 组成一个 12.8 km x 12.8 km 宏网格。
4. 中国范围使用 WGS84 / UTM 北半球 43N 至 53N，即 EPSG:32643 至
   EPSG:32653。
5. 每个 UTM 分区的规则网格原点固定为该投影坐标中的 `(0 m, 0 m)`；
   `grid_col` 和 `grid_row` 由 1,280 米整数网格计算。
6. patch 中心按经度半开区间唯一归属一个 UTM 分区。分区西边界包含，东边界
   不包含；最东侧研究边界按最终分区闭合处理。
7. 候选判定采用“中心点位于冻结中国研究边界内”。边境和海岸 patch 的
   footprint 可以跨出研究边界。
8. footprint 先在所属 UTM 中生成严格米制正方形，再转换为 WGS84 / EPSG:4326
   交付；不得使用经纬度差近似 1,280 米。

## 4. 唯一标识

每个完整网格 patch 至少保存以下字段：

| 字段 | 含义 |
| --- | --- |
| `patch_id` | 基于 UTM 分区和整数行列生成的全局唯一编号 |
| `grid_id` | `utm43n` 至 `utm53n` |
| `grid_epsg` | EPSG:32643 至 EPSG:32653 |
| `grid_col` / `grid_row` | 1,280 米规则网格整数行列 |
| `macro_id` | 所属 10 x 10 宏网格编号 |
| `longitude` / `latitude` | WGS84 中心点，X=经度、Y=纬度 |
| `utm_bounds` | 所属 UTM 中的精确米制范围 |
| `wgs84_bounds` | 转换后的 WGS84 范围 |
| `identity_hash` | 网格版本、EPSG 和整数行列组成的身份哈希 |
| `footprint_hash` | 规范化 WGS84 footprint 哈希 |
| `boundary_version` | 冻结研究边界版本 |
| `atlas_version` | 全国父网格版本 |

同一 `grid_epsg + grid_col + grid_row` 只能对应一个 patch。`patch_id`、
`identity_hash` 和 `footprint_hash` 均须唯一。

## 5. 输出设计

### 5.1 全国 GeoParquet 主图集

生成完整 patch 注册表，按 `grid_id` 分区保存为 GeoParquet 数据集。它是数据
下载、并行推理和结果汇总的权威输入。GeoParquet 保留完整字段和 polygon 几何，
避免 Shapefile 的字段名、编码和 2 GB 限制。

同时生成一个 manifest，记录总数、分区数量、边界版本、网格版本、字段模式、
生成命令、Git commit 和每个分区文件的 SHA-256。

### 5.2 分 UTM Shapefile

为 UTM 43N 至 53N 分别生成一套 footprint Shapefile，共 11 组。每组使用
WGS84 / EPSG:4326 交付，便于在 QGIS 和 ArcGIS 中查看；属性中保留短字段名，
完整字段以 GeoParquet 为准。

Shapefile 的 `.shp`、`.shx`、`.dbf`、`.prj` 和 `.cpg` 必须成套交付。若某个
分区任一组件接近 2 GB，则继续按固定 row block 分片，不能生成违反格式上限的
文件。

### 5.3 全国轻量索引

生成包含 60,043 个宏网格的 GeoPackage，图层包括：

1. `macrocells`：12.8 km 宏网格及准确 patch 数。
2. `utm_zones`：11 个 UTM 分区及各自 patch 数。

该文件用于全国快速浏览、任务分片和完成度统计，不承载约 574 万个完整 polygon。

### 5.4 可视化与说明

生成全国完整网格密度预览图、局部真实网格放大图、UTM 接缝示例图以及中文
`先读我.docx`。全国图只作内部技术预览；对外发布时使用符合地图管理要求的
标准底图。

## 6. 与 62,000 个候选的关系

将当前候选注册表按 `grid_epsg + grid_col + grid_row` 连接到全国父图集，并输出：

1. 成功唯一匹配数量。
2. 未匹配候选清单。
3. 一对多或身份冲突清单。
4. footprint 的拓扑一致性和最大坐标差。
5. 当前候选占完整父图集的真实比例。

目标是 62,000 个候选全部唯一匹配。任何未匹配或 footprint 不一致都视为阻断
问题，不通过人工改 ID 掩盖。

## 7. 规模与存储

现有宏网格面积估算约为 5,740,831 个陆地 patch，面积直接估算约为
5,859,375 个。最终数量以逐中心精确枚举为准，不在实现前写死。

初步按 575 万个 polygon 估算：

1. 分区 Shapefile 的 `.shp`、`.shx`、`.dbf`、`.prj` 和 `.cpg` 合计预计约
   2--5 GB；实际生成前先用一个 UTM 分区试运行外推，并逐组件检查 2 GB 上限。
2. GeoParquet 采用 ZSTD 压缩，初步预计约 1--4 GB，具体取决于几何编码和字段
   数量。
3. 生成时采用流式分区写入，不在内存中同时保留全国全部 geometry。
4. 临时空间按最终产物的 3 倍预留，并在 manifest 完成后删除中间文件。

存储估算必须在 UTM 50N 小规模试运行后更新，不能把规划值写成实测值。

## 8. 生成流程

1. 冻结 ADM0 边界、UTM 规则、网格版本和输出 schema。
2. 逐 UTM 分区投影研究边界，按 1,280 米整数行列枚举候选中心。
3. 应用唯一 UTM owner 规则和中心点边界判定。
4. 流式写入分区 GeoParquet，并累计准确宏网格 patch 数。
5. 从同一记录流写入分 UTM Shapefile。
6. 生成全国宏网格 GeoPackage、manifest 和预览图。
7. 对 62,000 个候选执行父网格成员关系审计。
8. 通过全部验收后冻结 atlas version 和 checksum。

## 9. 验收标准

1. 所有 `patch_id`、身份哈希和 footprint 哈希唯一。
2. 所有中心位于冻结研究边界内。
3. UTM owner 与中心经度一致。
4. 每个 footprint 投回 `grid_epsg` 后宽、高均为 1,280 米；面积为
   1,638,400 平方米，允许误差不超过 1 毫米和 1 平方米。
5. 同一 UTM 分区内不存在正面积重叠。
6. 跨 UTM 分区重叠不超过任一 patch 面积的 1%。
7. GeoParquet、Shapefile 和宏网格统计数量一致。
8. 62,000 个候选全部唯一映射到父图集。
9. 所有文件可读取，CRS 可识别，X=经度、Y=纬度。
10. SHA-256、ZIP 完整性和抽样重跑一致性检查通过。

## 10. 非目标

本次不下载季度遥感影像，不运行全国 embedding 推理，不把完整父网格标记为质量
合格训练集，也不处理 2020Q1 至 2021Q4 的云、缺测和配准质量。完整父网格只
冻结空间索引；影像可用性在后续数据生产阶段逐季度记录。
