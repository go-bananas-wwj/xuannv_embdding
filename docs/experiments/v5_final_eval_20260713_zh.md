## 3. 失败归因

1. **construction 能力无法"低成本移植"**。V4A 的 construction 突破依赖
   从零训练时 embedding 空间围绕教师语义重组；在 P10C 已固化的空间上，
   0.15 低强度蒸馏不足以重组，反而对 P10C 自有的 construction 方向
   产生干扰（-0.055，两个 checkpoint 一致，非噪声）。
2. **微调几乎不改变其他能力**：building/road/water、few-shot、检索
   全部在 ±0.01 内浮动——lr 2e-6 下参数漂移太小，"下行有界"的预期
   得到验证，但"上行"同样被锁死。
3. **确认方案第 4 节的备择结论**：*P10C 已是 320 patch 数据量 + 当前
   架构下的效果上界。蒸馏的收益（V4A construction）与判别结构的保持
   （P10C few-shot/检索）在现有数据量下不可兼得*——从零训会输判别，
   微调注不进语义。

## 4. 数据支持的下一步（算法侧到顶，杠杆在数据/形态）

1. **扩海淀数据**：时间窗 6→12 个月、扩相邻城区 patch 做预训练再特化。
   V4A 证明大数据量+蒸馏能建立更强语义，缺的是让判别结构也长在
   足够大的数据上。
2. **教师直用路线**：DINOv3-SAT493M 特征 + 64 维压缩头直接服务下游，
   我们的模型退居"压缩器"。V4A construction 0.6105 已暗示教师本身
   的上限远高于现有任何版本。
3. **双模型服务**（零训练成本，立即可用）：生产 P10C 兜底全任务 +
   V4A e800 专供 construction 检测（0.5988/0.6105 仍是全场最高）。
