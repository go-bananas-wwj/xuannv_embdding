# 玄女全国月度地理 Embedding V1 建设方案

> 版本：2026-07-20<br>
> 目标：使用约 1% 的中国陆地样本训练通用地理 embedding 模型，并在中国
> 全域生成每月一次、10 m 空间分辨率、64 维的 embedding 产品。<br>
> 训练主年份：2021 年。训练时序长度暂不写死，在试点消融后冻结；最终产品
> 仍按月生成 embedding。

## 1. 核心资源、时间与交付结论

### 1.1 显存需要多少

全国数据量增加不会把全部数据加载进显存。训练数据从磁盘分片流式读取，单卡
显存主要由模型参数、优化器状态、激活、单卡 batch、输入时序长度和重建分支
决定，与全国共有多少个 patch 不成线性关系。

当前同类 P10C 作业在 Ascend 910B 上实测每个训练进程约占 **12.2--12.6 GB
HBM**。全国版会增加标签分支，并且时序长度尚未冻结，因此采用更保守预算：

| 项目 | 估算 |
| --- | ---: |
| 当前同类作业实测 | 约 12.2--12.6 GB/卡 |
| 全国版预计实际峰值 | 约 20--32 GB/卡 |
| 全国版工程控制线 | 不超过 48 GB/卡 |
| 16 张 910B 预计实际占用 | 约 320--512 GB HBM |
| 16 张卡允许的工程上限 | 768 GB HBM |
| 16 x 64 GB 物理总 HBM | 1,024 GB，满足要求 |

结论：16 张 64 GB 910B 的显存足够。正式训练前必须以最终时序长度和全部损失
运行 16 卡 1,000-step 基准；任何单卡峰值超过 48 GB，都应先减小 batch、
启用激活检查点或减少同时解码的目标，而不是直接长训。

### 1.2 磁盘存储需要多少

一期使用 **62,000 个训练 patch、2021 年 12 个月数据**。根据用户提供的
《遥感影像（含产品、地面站数据）》清单，对计划使用的数据源逐项折算后，必须
区分三类容量：完整源档案、62,000 点原始裁窗、最终训练张量。三者不能相加后
再称为“训练数据大小”。

| 容量口径 | 计算结果 | 工程规划值 |
| --- | ---: | ---: |
| 清单内拟采用来源的 2021 完整档案 | 约 140.2 TB | 180--220 TB 可用空间 |
| 62,000 点原始裁窗 | 理论约 1.48 TB | 1.9--2.3 TB |
| 三类核心源最终张量 | 未压缩精确值 1.0605 TB | 1.1--1.3 TB |
| 高分目标、粗尺度目标、标签和索引 | 约 0.9--1.4 TB | 1.2--1.7 TB |
| **最终可训练数据包** | **约 2.0--2.7 TB** | **按 2.5--3.0 TB 验收** |
| **含原始裁窗、双处理版本、缓存和 checkpoint 的峰值** | - | **约 8--12 TB** |

因此，如果数据中心可以按 patch 裁窗交付，建议训练工作区准备 **至少 16 TB
可用空间，优选 24 TB 物理容量**。如果只能接收完整 2021 整景，则源档案应
使用独立存储池，至少准备 220 TB 可用空间，并按 300--400 TB 物理容量建设，
不能与训练工作盘混放。详细逐源计算见第 6.2 节。

### 1.3 16 张 910B 训练多久

全国训练按固定优化步数计算，不沿用海淀小数据的 800 epoch。按当前 P10C
实测速率、有效全局 batch 96、16 卡扩展效率 70%估算：

| 目标 | 纯训练 | 含 checkpoint、故障和固定评测缓冲 |
| --- | ---: | ---: |
| 10 万 updates 试验版 | 约 14.9 天 | 约 18 天 |
| **20 万 updates 正式版** | **约 29.8 天** | **约 36 天** |
| 40 万 updates 长训版 | 约 59.7 天 | 约 72 天 |

一期按 **20 万 updates、约 36 天**排期。训练时序长度改变后，需要用 1,000-step
实测结果重新校准，不能把 36 天当作无条件承诺。

### 1.4 全国逐月产品和总工期

全国全覆盖约 586 万 patch/月。全国导出只采用完成优化后的 16 卡批量流水线，
目标吞吐为单卡 3--5 patch/s、端到端聚合不低于 35 patch/s：

- 全国一个月：约 1.2--2.0 天；
- 全国 12 个月：约 15--25 天；
- 产品索引、质量检查和下游验收：另留 7--12 天。

项目从 2026-07-20 启动，最终 DDL 按 **2026 年 11 月上旬**倒排。数据审计、
试点、训练、全年导出、评测和排错合计预留约 **105--110 天**，详细日期见
第 11 节。

## 2. 全国样本怎么选

### 2.1 基础空间网格

全国陆地先按不同 UTM 分区建立规则网格。每个训练 patch 的物理范围为
`1280 m x 1280 m`，对应 `128 x 128` 个 10 m 像素，单个 patch 覆盖
`1.6384 km2`。

中国陆地面积按约 960 万 km2 估算，全覆盖约有：

```text
9,600,000 / 1.6384 = 5,859,375 个 patch
```

直接训练全部约 586 万个 patch 超出当前数据、存储和算力条件，因此一期只
选择约 1%。

### 2.2 全国基础 1% 怎么实现

基础抽样不是按文件编号每 100 个取 1 个，而是在真实二维地理网格上抽样：

1. 将相邻的 `10 x 10` 个 patch 组成一个宏网格；
2. 一个完整宏网格内含 100 个候选 patch；
3. 使用固定随机种子和 `patch_id` 的 SHA-256 哈希，对 100 个候选排序；
4. 选中哈希排名第一且位于中国陆地边界内的 patch；
5. 同一输入边界、网格版本和随机种子永远得到同一批样本，可复现且可审计。

对于海岸、国界附近不足 100 个有效 patch 的残缺宏网格，不能无条件选 1 个，
否则边界地区会被过采样。若宏网格实际有 `n` 个有效候选，则以 `n/100` 的
概率接纳该宏网格，接纳后再选其中哈希排名第一的 patch。这样每个有效 patch
的期望入选概率仍约为 1%。

理论上全国 1% 约为 58,594 个 patch；经过国界、岛屿和完整 patch 中心检查后，
当前基础空间样本为 **57,405 个**。

![全国基础1%空间抽样分布](assets/china_v1_2021_multisource/national_static_1pct_sampling_preview.png)

**图 1  全国基础 1% 空间抽样分布。** 红点表示 57,405 个通过国界几何检查的
`1280 m x 1280 m` 基础候选 patch 中心。该图尚未叠加 2,595 个空间分层补样、
500 个海岸补样和后续 1,500 个语义/困难区域增量补样，也尚未执行 2021 年
逐月影像质量筛选。

### 2.3 城市和其他重要区域怎么补采样

纯 1% 均匀抽样能够保证全国覆盖，但城市、道路、湿地、雪地和工业区等稀有
地物可能在样本中占比不足。补采样分两步完成。

#### 第一步：空间均衡补采样

当前已经增加 **2,595 个空间分层样本**，将基础样本补到 60,000 个：

- 按 UTM 空间分区分组；
- 分配数量与分区面积的平方根成比例；
- 大区域得到更多样本，但小区域不会因为面积小而完全被忽略；
- 每个宏网格原则上最多新增 1 个 patch；
- 与基础样本去重，仍使用固定种子哈希选择。

需要说明：当前 2,595 个样本是空间均衡补样，还不是完整的城市语义补样。

#### 第二步：语义和困难区域补采样

在 WorldCover、OSM、DEM 和影像质量统计完成后，**不删除、不替换现有
60,500 个 patch**，直接增加 **1,500 个语义和困难区域 patch**，最终达到
62,000 个。新增名额建议分配为：

| 补样类型 | 新增数量 | 主要依据 |
| --- | ---: | --- |
| 城市和建成区 | 500 | WorldCover 建成比例、OSM 覆盖和行政区均衡 |
| 稀有自然地物 | 400 | 湿地、雪地、高原、裸地、河湖和绿洲 |
| 稀有基础设施 | 300 | 铁路、机场、港口、工业、教育和体育设施 |
| 困难观测区 | 300 | 长期多云、缺测、传感器差异大和复杂地形 |
| **新增合计** | **1,500** | 与现有 60,500 个 patch 去重 |

具体候选优先级包括：

- 城市和建成区；
- 农田、森林、草地、灌木、裸地；
- 永久水体、湿地、雪地和高原；
- 铁路、机场、港口、工业区；
- 施工、采石、填埋场；
- 教育和体育设施；
- 长期多云、缺测或不同传感器差异较大的困难区域。

城市补样使用 WorldCover 建成区比例、OSM 已知覆盖和行政区域共同评分，不用
最终人工下游标签挑选。任何单一地区在同一类别中的占比不超过 40%，每个
宏网格最多补 1 个样本，防止北京、上海等少数大城市占满城市样本。

补样只从现有 60,500 个 patch 之外选择，并保存 `sampling_reason`。如果某类
候选不足，其剩余名额按“困难观测区 -> 稀有自然地物 -> 城市”的顺序回填，
但最终新增总量保持 1,500。正式冻结 2021 年清单前，需要完成这部分增量补样
代码、去重检查和全国分布可视化。

### 2.4 海岸线数据怎么补

海岸线单独补充 **500 个 patch**：

1. 使用独立的 Natural Earth 海洋面数据，而不是只看中国行政边界；
2. 只保留宏网格同时接近陆地和真实海洋面的区域；
3. patch 中心到海洋面的距离上限约 `0.035°`，约 3--4 km；
4. 按沿海 UTM 分区分配名额，避免集中在某一个省；
5. 与基础和空间补样去重；
6. 河流国界、湖泊边界和省界不会被误认为海岸线。

海岸补样用于学习陆海边界、港口、滩涂、养殖区、河口和近海水体等语义。

### 2.5 一期最终样本组成

| 样本层 | 数量 | 作用 |
| --- | ---: | --- |
| 全国基础空间样本 | 57,405 | 约 1% 全国陆地空间骨架 |
| 空间分层补样 | 2,595 | 平衡不同 UTM 分区和小区域 |
| 海岸线补样 | 500 | 增强真实陆海交界 |
| 城市/稀有地物/困难区域增量补样 | 1,500 | 不替换现有样本，直接新增 |
| **合计** | **62,000** | 约占中国全覆盖 patch 的 1.06% |

一期冻结为 62,000 个 patch。后续若扩大到 1.25%或更高，必须单独增加存储
和训练预算，不能悄悄改变“一期约 1% + 少量重点补样”的统计口径。

## 3. 为什么先做 1%

### 3.1 参考 AEF 的代表性空间抽样

AlphaEarth Foundations 公开报告约 841 万个训练地点，空间覆盖约占全球陆地
**1.1%**，工程上可以概括为约 1%。它证明了地理基础模型不必把全球每个像素
都放入训练，而可以通过广覆盖、强质量控制和多模态学习获得可迁移 embedding。

但需要准确表述：我们借鉴的是“约 1% 的代表性覆盖”思想，不代表 62,000 个
中国样本等价于 AEF 的 841 万地点、30.48 亿帧和 512 TPU v4 训练规模。

### 3.2 当前机器和存储只适合先做 1%

当前计划使用 16 张 Ascend 910B，每张约 64 GB HBM，总 HBM 约 1 TB。
训练时数据由 Zarr/WebDataset 分片流式读取，不会把全部训练集一次载入显存；
建议单卡峰值控制在 48 GB 以下，给 HCCL 通信和内存碎片留出空间。

62,000 个 patch 的表内源数据原始裁窗约 1.9--2.3 TB，最终可训练数据包按
2.5--3.0 TB 验收；把双处理版本、缓存和试验产物纳入后，建设阶段按 8--12 TB
峰值规划。若直接训练中国全覆盖 586 万 patch，数据和训练访问量约放大 95 倍，
当前存储、I/O 和 16 卡训练时间都无法接受。

推荐训练硬件：

| 项目 | 16 张 910B 建议配置 |
| --- | --- |
| NPU | 2 个同构 8 卡节点，16 x 64 GB HBM |
| 单卡 HBM 控制线 | 不超过 48 GB |
| 每节点 CPU 内存 | 至少 512 GB |
| 每节点本地 NVMe | 8--16 TB，用于热数据缓存和分片预取 |
| 聚合顺序读取 | 至少 2 GB/s，优选 4 GB/s |
| 节点互连 | 双 200 Gb/s RoCE/IB 或同等级网络 |

## 4. 为什么使用现有数据而不是主要依赖互联网下载

全国 Sentinel、Landsat 和高分影像通过公共互联网逐景读取时，容易受到跨境
网络、签名过期、服务器限流、HTTP range request 失败和重复重试影响。当前
全国下载任务已经验证：即使有断点续传和 watchdog，公网物化速度仍远低于
训练所需速度。

因此本版采用以下原则：

1. 以单位现有遥感数据档案作为主体；
2. 优先使用已经落盘、授权清楚、带日期和投影的数据；
3. 公网只补充体量较小的标签、索引、元数据和确实缺失的来源；
4. 如本地没有全国完整 Sentinel-1/2，优先通过数据中心离线拷贝或对象存储
   批量迁移，不使用当前单机公网窗口下载作为正式生产路径；
5. 不为了凑齐模态，把下载失败或云量过大的数据当成有效影像。

现有 2025-04 至 2026-04 的公网下载结果保留为数据管线验证和未来时间泛化
素材，但不再把它当作 2021 全国主训练数据的唯一来源。

## 5. 为什么选择 2021 年

### 5.1 2021 是多源数据共同覆盖最多的一年

数据不必是最新年份，关键是不同传感器和标签在同一时间段能够对齐。现有清单
中很多产品的最新时间只到 2021 年；另一些产品虽然有 2022、2023 或更晚数据，
但共同交集明显减少。

2021 年可以同时使用：

- Sentinel-2 全国全年光学；
- Sentinel-1 全国全年 SAR；
- Landsat-8 全国全年，Landsat-9 从 2021 年 12 月补充；
- GF1、GF2、HJ2A/HJ2B、ZY2、CB04A、GF6、GF7、吉林一号等国产影像；
- ESA WorldCover 2021；
- WorldCereal 2021；
- MODIS 植被、地表温度、LAI 和 GPP；
- ALOS PALSAR 2021；
- 2021 历史 OSM、DEM 和水体产品。

因此，2021 是现有数据中“不是所有数据最新，但共同可用源最多”的年份。

### 5.2 为什么首版只选择一年

首版只选择一年，不是因为模型只能学习一年，而是因为 **2021 年拥有最多的
共同多源数据**。如果同时引入多年份，很多来源只在部分年份存在，模型可能把
“传感器是否存在”误学成“年份差异”，同时显著增加存储、配准和训练风险。

本阶段先保存 2021 年完整 12 个月档案。训练时到底使用单月、相邻多月、随机
月份还是全年上下文，暂不写死；在 2,000 patch 试点中通过下游 probe、变化
敏感性、显存和吞吐消融后冻结。无论最终训练上下文长度是多少，产品目标仍是
每个月生成一张 embedding。2023 和 2025--2026 年用于后续跨年份验证。

## 6. 每个月需要多少训练数据

### 6.1 每月核心输入

| 来源 | 作用 | 月度处理 |
| --- | --- | --- |
| Sentinel-2 L2A | 主光学输入 | 选局部最清晰的 1--2 景，SCL 生成像素掩膜 |
| Sentinel-1 RTC | 全天候 SAR | VV/VH 月度合成，保留有效掩膜，重建权重较低 |
| Landsat-8/9 C2 L2 | 独立光学 | L8/L9 统一标度，QA_PIXEL 生成像素掩膜 |

按 62,000 patch、`128 x 128` 和当前 Zarr FP32 schema 计算后，再增加工程
余量，采用以下保守预算：

| 内容 | 每月 | 12 个月 |
| --- | ---: | ---: |
| S2/S1/Landsat 动态数组和掩膜 | 约 90--110 GB | 约 1.08--1.32 TB |
| MODIS/ERA5 等月度粗尺度目标 | 约 3--10 GB | 约 36--120 GB |
| 月度质量记录、索引和分片冗余 | 约 7--30 GB | 约 84--360 GB |
| **动态数据规划值** | **约 100--150 GB/月** | **约 1.2--1.8 TB/年** |

WorldCover、OSM、DEM、年度 PALSAR 和一份最佳高分光学不应每月重复保存：

| 静态/年度内容 | 一次性存储预算 |
| --- | ---: |
| OSM、WorldCover、DEM、静态标签 | 50--150 GB |
| PALSAR、WorldCereal、土地覆盖辅助目标 | 100--300 GB |
| 2--5 m 稀疏高分光学目标 | 300--1,000 GB |
| 清单、统计、QA 图和日志 | 50--150 GB |

加上原始交付暂存、1--2 TB 临时重投影和重试空间、两套可恢复处理版本，以及
checkpoint 和评测产物，训练建设阶段按 **8--12 TB** 峰值规划。建议至少准备
**16 TB 可用空间，优选 24 TB 物理容量**。

### 6.2 根据原始数据清单复算 62,000 点容量

原始 CSV 的“数据大小（MB）”字段并不是统一的 MB 口径。例如 GF1 的
`13086.72` 与同一行 `12.78 TB` 对应的是 GB 到 TB 的换算；另一些全球产品
又确实按 MB 记录。因此本次以“数据大小（TB）”列作为清单标称容量，并保留
单位不一致带来的工程余量。本次测算对应输入清单的 SHA-256 为
`91fc81e02ac836683325e9edb1c9312c7c4299c24f2088a324f11ee60b4f1907`。

本次纳入估算的来源分为三组：

- 核心月度源：Sentinel-1、Sentinel-2、Landsat-8 和 2021 年 12 月的
  Landsat-9；
- 稀疏高分/补充源：CB04A、GF1、GF2、GF6、GF7、HJ2A/HJ2B、ZY2、
  JL1GP01/02、黑土地 JL1 和 Hi-GLASS；
- 粗尺度物理目标：清单中的 MODIS 植被指数、地表温度、LAI 和 GPP 产品。

折算规则为：多年产品按覆盖年数均分到 2021 年，Landsat-9 按 37 个月中的
2021 年 12 月折算；62,000 点的空间面积占比为：

```text
62,000 x 1.6384 km2 / 9,600,000 km2 = 1.05813%
```

| 数据组 | CSV 所列完整时段容量 | 折算的 2021 容量 | 62,000 点理论裁窗 |
| --- | ---: | ---: | ---: |
| S1/S2/Landsat 核心源 | 402.87 TB | 54.92 TB | 0.581 TB |
| 国产/商业高分与 Hi-GLASS | 236.11 TB | 84.46 TB | 0.894 TB |
| MODIS 粗尺度物理目标 | 16.83 TB | 0.823 TB | 0.009 TB |
| **合计** | **655.81 TB** | **140.21 TB** | **1.484 TB** |

OSM、WorldCover、DEM、WorldCereal 和 PALSAR 等不在该 CSV 的外部标签或辅助
产品没有混入 140.21 TB；它们在最终训练数据包中另设 0.2--0.3 TB 预算，待
数据版本和许可冻结后用真实字节数替换。

`1.484 TB` 是按面积比例得到的理论净载荷。实际裁窗会遇到 COG block 扩读、
边界重叠、候选景质量筛选、重投影临时块和失败重试，因此原始裁窗区按
**1.9--2.3 TB** 规划。高分数据并非全国均匀覆盖，0.894 TB 是按清单容量和
均匀空间分布得到的保守上界；最终以 62,000 点与真实景 footprint 的相交统计
为准。

当前核心物化代码保存 12 个 S2 通道、2 个 S1 通道和 7 个 Landsat 通道，均为
FP32，并为三类源各保存一个 uint8 有效掩膜。最终核心训练张量可精确计算为：

```text
像素位置数 = 62,000 x 12 x 128 x 128
21 个 FP32 通道 = 1.023934464 TB
3 个 uint8 掩膜 = 0.036569088 TB
核心张量未压缩合计 = 1.060503552 TB
```

Zstd 压缩会降低影像数组本体，但还要保存质量记录、场景索引、分片元数据和
校验，因此核心训练分片按 **1.1--1.3 TB** 验收。再加入高分目标、粗尺度目标、
OSM/土地覆盖标签和统计后，最终可训练数据包按 **2.5--3.0 TB** 预留。

以上仍是规划值，不代替试点实测。2,000 点试点必须同时报告：源文件读取字节、
裁窗净字节、Zarr 实际字节、压缩比、临时峰值和失败重试字节，再按
`62,000 / 2,000` 外推并增加 20%余量。若实测超过 3.0 TB，必须先更新容量和
DDL，再开始全量物化。

## 7. 数据按不同交付方式需要多少存储

原 CSV 的“MB”和“TB”列存在单位不一致，例如 `13086.72 MB` 被写成
`12.78 TB`，因此下面是工程预算，不是数据提供方已经确认的精确字节数。

### 7.1 能按 2021 年、按训练 patch 窗口读取

这是推荐方案。只保留 62,000 个训练位置需要的窗口和质量掩膜：

- 表内来源对应的原始裁窗约 1.9--2.3 TB；
- 最终可训练数据包按 2.5--3.0 TB 验收；
- 含原始裁窗、两套处理版本、缓存、checkpoint 和评测的峰值约 8--12 TB；
- 建议至少 16 TB 可用，优选 24 TB 物理容量。

### 7.2 能按 2021 年下载，但必须下载完整整景

如果数据平台只能按年份提供整景，不能按 patch 裁窗，本次清单内拟采用来源的
2021 年净载荷约 **140.2 TB**。考虑年份分布不均、CSV 单位问题、解压、索引和
交付冗余，源档案至少按 **180--220 TB 可用空间**规划；若同时保留处理中间态、
一个可恢复处理版本和备份，建议建设 **300--400 TB 物理容量**的独立存储池。

该估算必须在数据提供方确认每个来源的 2021 景数、波段、位深和真实单位后更新。

### 7.3 不能按年份下载，必须接收相关数据集全部历史

按 CSV 中与本方案相关的 Landsat、Hi-GLASS、GF、HJ、ZY 和吉林一号数据集
名义容量相加，已经接近 **0.8--1.0 PB**，尚未可靠计入完整 Sentinel-1/2
和辅助产品。考虑单位错误、解压、处理中间态和副本，建议按 **1.5--2 PB
物理容量**单独立项，不能放入当前训练数据盘。

所以首选顺序是：

```text
2021 + patch窗口  >  2021完整整景  >  全部历史档案
```

## 8. 可使用的标签数据

### 8.1 训练弱标签

| 标签 | 分辨率/年份 | 作用 | 注意事项 |
| --- | --- | --- | --- |
| OSM 历史快照 | 矢量，2021 或更早 | 建筑、道路、铁路、水体、土地利用、工业、商业、教育、体育 | 空白是 unknown，不是 background |
| ESA WorldCover 2021 | 10 m，11 类 | 林地、草地、耕地、建成区、水体、湿地等宽类 | 来自 S1/S2，不作为独立评测真值 |
| WorldCereal 2021 | 10 m | 作物、谷物、灌溉等农业语义 | 只在官方有效季节和高置信区域监督 |
| GLC_FCS30D 2021 | 30 m，35 类 | 更细土地覆盖 | 低权重或用于标签一致性筛选 |
| Dynamic World 2021 | 10 m，9 类概率 | 逐景概率与不确定性 | 来自 S2，不作为唯一教师 |
| JRC Global Surface Water | 30 m，月度 | 永久水体、季节水体和变化 | 若用于训练，不能直接作为最终测试真值 |
| Copernicus DEM GLO-30 | 30 m | 高程、坡度、坡向 | 连续物理目标，不是土地类别 |
| ALOS PALSAR 2021 | 25 m | 森林、湿地、结构信息 | 保留 QA，低权重辅助目标 |

OSM 建议合并为 16 个稳定大类：building、major_road、minor_road、
path_walk、railway、permanent_water、wetland、forest_green、agriculture、
residential、commercial、industrial、construction_quarry_landfill、education、
sports_playground、airport_port。

每一类都保存 `known_mask` 和 `confidence`。多源标签一致时正常监督；只有一个
来源时降低权重；明显冲突时关闭语义损失，只保留自监督重建。

### 8.2 独立评测标签

训练标签和最终评测标签必须分开：

- 土地覆盖：CLCD 2021 与 GLC_FCS30D 二选一进入训练，另一个作为空间留出测试；
- 建筑和道路：使用独立测绘数据或分省人工抽样复核；
- 水体：使用人工修订的高分影像/JRC 样本；
- 农业：使用 WorldCereal 独立参考样本；
- 森林：使用空间留出的 GEDI 足迹或森林样地；
- few-shot：按省份和生态区切空间块，不能随机切像素。

最终论文主结果至少使用 5 个空间 fold，并报告 F1、AP、AUC、mIoU、检索
Recall@K、变化检测指标和可视化，不能只看 AUC。

## 9. 16 张 910B 训练一版需要多久

### 9.1 训练不能继续用 800 epoch 口径

海淀 320 patch 使用 800 epoch 是因为样本少。全国 62,000 patch 若仍写
800 epoch，会产生完全不同的更新量。因此全国模型按固定 updates 训练。

当前 P10C 实测：6 张 910B、320 patch、800 epoch，共 256,000 patch-visits，
耗时 17.8256 小时，约为 `2,393.6 patch-visits/卡·小时`。

假设：

- 16 张同构 910B；
- 每卡 batch 3，梯度累积 2；
- 有效全局 batch 96；
- 两节点扩展效率 70%；
- BF16/FP16 与分片顺序预取正常。

则：

| 训练目标 | 数据访问量 | 纯训练时间 | 含 20% 缓冲 |
| --- | ---: | ---: | ---: |
| 10 万 updates | 960 万 patch-visits | 约 14.9 天 | 约 18 天 |
| **20 万 updates** | **1,920 万** | **约 29.8 天** | **约 36 天** |
| 40 万 updates | 3,840 万 | 约 59.7 天 | 约 72 天 |

一期正式版建议先训练 **20 万 updates，预计约 36 天**，相当于约 1,920 万
patch-visits。具体时序采样方式暂不写死，由试点消融决定。正式承诺工期前必须
先做 16 卡 1,000-step 基准；扩展效率低于 70%时，应先修数据 I/O 和 HCCL，
而不是直接开始一个月长训。

## 10. 全国逐月 embedding 提取需要多久

### 10.1 计算规模与性能门

中国全覆盖约 5,859,375 个 patch：

```text
单月：约 586 万 patch
12个月：约 7,031 万 patch-month
```

全国排期只采用优化后的导出目标，不按旧的逐 patch `.pt` 导出速度计算。
正式训练开始前必须完成：

1. 16 卡按空间 shard 并行；
2. Zarr/WebDataset 连续预取；
3. batch 推理，不逐 patch 初始化模型；
4. 直接写 FP16/int8 Zarr 或 COG，不生成数百万个 `.pt` 小文件；
5. 计算、量化和写盘流水线重叠；
6. 支持 shard 级断点续传和 checksum。

优化目标为单卡 `3--5 patch/s`，16 卡端到端聚合吞吐不低于 **35 patch/s**。
达标条件必须同时包含读取、模型前向、量化、写盘和 checksum，不能只测模型
前向。按该吞吐计算：

| 导出范围 | 优化后预计时间 |
| --- | ---: |
| 全国一个月 | 约 1.2--2.0 天 |
| 全国 12 个月 | 约 15--25 天 |
| QA、索引、拼接和抽样复核 | 约 3--7 天 |

在正式训练前必须用 10,000 patch 做一次端到端导出基准。连续三次均达到
`>=35 patch/s`、没有丢 patch、断点恢复成功、量化后固定下游指标下降不超过
预设容差，并且按实测压缩比推算的全国单月产品不超过 6.5 TB，才允许采用
上表工期和 70--80 TB 全年容量预算。否则先优化，不能带着未验证吞吐或容量
进入长训。

### 10.2 全国产品存储复算

中国陆地约有 960 亿个 10 m 像素。计算过程如下：

```text
中国陆地面积 = 9,600,000 km2 = 9.6 x 10^12 m2
10 m 像素面积 = 100 m2
有效陆地像素数 = 9.6 x 10^12 / 100 = 96,000,000,000
int8 单像素 = 64 维 x 1 Byte = 64 Byte
int8 单月 = 96,000,000,000 x 64 = 6.144 TB
int8 12个月 = 6.144 x 12 = 73.728 TB
```

因此，73.7 TB 是全国陆地、12 个月、64 维 int8 的**未压缩基础载荷**，不是
估算错误。真正优化点是：只保存有效陆地、去除 patch 重叠、int8 量化、按
空间块压缩，以及不生成数百万个独立小文件。

| 产品范围 | 未压缩 int8 | 预计优化后 | 规划值 |
| --- | ---: | ---: | ---: |
| 62,000 个训练 patch，单月 | 65.0 GB | 40--55 GB | 60 GB |
| 62,000 个训练 patch，12个月 | 780 GB | 500--650 GB | 0.8 TB |
| 全国全覆盖，单月 | 6.14 TB | 4.1--5.2 TB | 5.5--6.5 TB |
| 全国全覆盖，12个月 | 73.7 TB | 49--62 TB | **70--80 TB** |

上述“优化后”假设 int8 embedding 的分块压缩比约 1.2--1.5。embedding 可能
接近高熵数据，不能按影像反射率的高压缩比计算，所以采购和交付仍按 70--80 TB
单版本规划。该值包含索引、量化参数、质量掩膜和约 10%--20%工程余量。

作为对照，完全不量化时的基础载荷为：

| 编码 | 单月 | 12 个月 | 单版本生产建议 |
| --- | ---: | ---: | ---: |
| FP32 | 24.6 TB | 295 TB | 不建议全国发布 |
| FP16 | 12.3 TB | 147 TB | 只保留抽样验证区 |
| int8 未压缩 | 6.14 TB | 73.7 TB | 优化后按 70--80 TB/版本规划 |

推荐发布 int8，并保留分块/分通道量化参数；FP16 只保存小规模验证区和必要
中间结果。双副本 int8 全年月产品规划约 **140--160 TB**。

这里的“全国”是中国全域。如果真正提取全球陆地 12 个月 embedding，像素和
计算量约为中国的 15.5 倍，仅 int8 基础载荷就约 1.14 PB，不属于本期目标。

## 12. 预计能达到什么效果

这一版的目标不是直接复制 AEF 的全球规模，而是得到一个更适合中国、具备月度
时序能力的全国地理 embedding 底座。

合理预期：

- 在中国全域形成空间连续、每月更新的 64 维 embedding；
- 对水体、森林、农田、城市建成区和宽类土地覆盖形成较清晰的语义聚类；
- 使用少量标签和 linear/MLP/conv3x3 轻量头完成建筑、道路、水体、土地利用、
  绿地和农业等快速制图；
- 支持相似区域检索、跨省迁移和月度变化检测；
- 宽类地物和生态语义预计优于只用海淀训练的模型；
- 月度变化任务有机会优于只有年度产品的 AEF。

需要保持审慎：

- 62,000 个地点远少于 AEF 的 841 万地点，不能提前承诺全国所有任务超过 AEF；
- 建筑边界、窄道路和小目标取决于国产高分覆盖、配准和稀疏重建质量；
- 西部高原、长期多云区和 OSM 稀疏区仍可能较弱；
- 模型是否达到生产标准必须由独立空间测试和真实 few-shot 业务任务决定。

建议把一期验收定义为：相同标签、相同空间 split 和相同轻量头下，在多数宽类
土地覆盖和核心 few-shot 任务接近或超过 AEF/传统基线；在月度变化任务上体现
清晰优势；全域 PCA 不出现系统性 patch 接缝、云雾块和省域颜色漂移。
