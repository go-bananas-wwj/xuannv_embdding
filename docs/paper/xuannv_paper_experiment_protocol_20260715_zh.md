# 玄女月度地理嵌入论文实验协议

## 1. 论文定位

论文定位为城市尺度月度索引多模态嵌入框架，不将玄女表述为全球基础模型。核心问题是：冻结64维月度索引嵌入后，能否通过少量标注和轻量下游头完成多类城市地物制图。P10C使用跨月份注意力和跨日期聚合的较高分辨率上下文，因此“月度索引”不等于“只看当月”。

主标题暂定：

> XuannvEarth: A City-Scale Monthly Multimodal Embedding Framework for Label-Efficient Urban Mapping

## 2. 统一评测规则

- 主评测使用连续空间block 5-fold，而不是随机patch划分。
- 每折使用一个连续地理带测试、相邻地理带验证，并从训练集剔除一格空间缓冲区。
- 所有玄女、AEF、DINOv3和Raw基线共用相同split、shot、head、seed与训练预算。
- 阈值只在验证集选择；正文报告测试集`F1@validation threshold`、AP、AUC-ROC和IoU。
- 测试集oracle最佳F1只作为附加上限，不作为论文主指标。
- 主表报告5-fold × 3-seed均值、标准差和空间patch配对置信区间。

固定split：`configs/eval/haidian_spatial_5fold_buffer1_seed42.json`。

## 3. 实验矩阵

| 编号 | 实验 | 目的 | 当前决策 |
|---|---|---|---|
| E0 | P10C生产版全域案例 | 展示传导式区域产品 | 必做；禁止进入空间泛化主表和配对CI |
| E1 | 40/80/150严格嵌套数据规模 | 判断数据规模影响 | 旧实验降为探索；重新训练；160仅保留为fold 0 pilot |
| E2 | 无OSM、仅粗OSM土地利用、probe无hard-negative、完整配方 | 分离粗弱语义、细粒度probe与困难背景作用 | 旧实验初始化受污染；重新训练 |
| E2-HR | 去较高分辨率来源的完整路径 | 测试输入融合与重建监督的合并作用 | 必做；若要拆分因果作用须做2×2消融 |
| E2-Mask | 去结构化输入破坏 | 验证困难重建作用 | 必做 |
| E3 | 5-fold × 3个下游seed轻量probe | 估计空间与下游采样波动 | 已完成随机fold版；空间版重跑；不得称3个encoder seed |
| E4 | 独立人工标签 | 检验不同标签源下的趋势 | 必做；不能消除上游OSM监督不对称；按注册标注协议执行 |
| E5 | 哈尔滨从零训练 | 验证配方可复现 | 当前训练继续完成；不称零样本泛化 |
| E5-ZS | 海淀模型直接测试哈尔滨 | 跨城市迁移 | 建议补充 |
| E6 | Raw/AEF/DINOv3统一基线 | 比较冻结表示的下游可用性 | 分为原生产品比较和统一64维/信息预算匹配比较 |
| E7 | 匹配重训的1/3/6个月模型与时间对照 | 评估时间上下文价值 | 推理期删月/打乱仅作分布偏移鲁棒性，不作因果证据 |
| E8 | 晴空率/缺模态分层评测 | 验证云雾和缺测鲁棒性 | 低成本必做 |

## 4. 训练数据划分

空间fold 0包含64个测试patch、64个验证patch和20个缓冲patch，剩余172个候选训练patch。五折候选训练池分别为172、157、150、176和151，因此完整空间5-fold scaling必须使用每折严格嵌套的40/80/150个patch；固定清单保存于`configs/eval/haidian_paper_subsets_40_80_150_seed42.json`，由不使用标签的确定性maximin空间采样脚本生成。测试patch不参与embedding训练、验证或checkpoint选择。现有160-patch训练仅作为fold 0 pilot，不进入完整5折scaling主结论。

生产版P10C使用海淀全域训练，因此其原有结果属于城市内传导式制图。论文将同时报告该业务设置和空间独立设置，禁止混为一种泛化结论。

## 5. 当前实验处理

- E5哈尔滨训练继续到800 epoch。它已经消耗约350 epoch，且可用于验证配方在第二城市能否重现。
- 旧E1权重保留，但不再导出或执行论文主评测，因为其训练子集不严格嵌套且与验证集重叠。
- 旧E2权重保留为开发记录，但不进入因果消融表，因为初始化已接受OSM语义监督。
- E3随机fold统计、E4 ESRI结果、E6 fold0结果保留为诊断和补充材料，不作为论文最强泛化证据。
- 完整OSM模型在建筑、道路、水体等重叠类别上的结果只能称为“OSM辅助条件下的标注效率”；更一般的表示结论必须依赖held-out类别、no-OSM模型和独立人工标签。
- 论文数值必须遵守`docs/paper/jrs_2026/registered_evaluation_protocol.md`；当前仍读取任务本地随机split或会静默缩小shot数量的旧脚本不得生成正文结果。

## 6. 启动顺序

1. E5完成后先导出哈尔滨embedding并执行统一空间评测。
2. 两卡一组并行训练E1/E2第一批：fold 0完整160 pilot、完全无OSM、仅粗OSM土地利用；后续完整5折主实验统一使用注册的150上限。
3. 第二批训练：probe无hard-negative、去高分、去结构化mask。
4. 第三批并行训练完整40与完整80。
5. 每个checkpoint导出后立即执行同split的轻量probe，汇总后删除中间embedding，只保留最终结果与必要可视化。
6. 并行完成人工独立标签；E7主结论使用匹配重训的1/3/6个月模型，推理侧时序破坏只保留为鲁棒性补充实验。

## 7. 论文数值门禁

- 科学模型固定使用训练期总验证目标最低的`best.pt`；不得用下游测试结果在epoch 600、800或其他checkpoint之间挑选。
- 下游主比较统一到训练折拟合的64维输入和固定Conv3×3头；Raw主对照使用与玄女相同的六个月信息窗口。
- shot、阈值、CI、OSM任务轨道、独立标注和实现门禁的精确定义见`docs/paper/jrs_2026/registered_evaluation_protocol.md`。
- 旧脚本修复注册split、shot失败策略和信息预算之前，只能产出开发诊断结果。
